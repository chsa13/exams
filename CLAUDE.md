# Инструкция для Claude: сборник FoCUs — подготовка к экзаменам ЦУ

Сайт https://chsa13.github.io/exams/ — сборник тренажёров к коллоквиумам и контрольным. Экзаменов будет много,
и все они должны быть устроены и написаны **одинаково**. Этот файл — как работать; устройство кода и заметки
по каждому экзамену — в `DESIGN.md`.

## 1. Главное правило: всё единообразно

- **Новый экзамен повторяет устройство существующих.** Не придумывай новую структуру, формулировки или оформление —
  возьми ближайший экзамен-образец (§2) и сделай так же.
- **Любая новая просьба «делай по-другому» — это новое правило для всех экзаменов.** Если пользователь просит изменить
  формулировку, порядок разделов, оформление, поведение страницы — в том же изменении:
  1. переделай **все** экзамены, включая старые;
  2. обнови правило в этом файле (и в `DESIGN.md`, если там описано старое поведение);
  3. если правило можно проверить автоматически — добавь или поправь проверку в `tests/style.test.ts`.

  Только для одного экзамена — лишь если пользователь прямо так сказал; тогда запиши исключение в раздел этого экзамена
  в `DESIGN.md`.
- **Общее — в коде, а не в текстах экзаменов.** Надпись, одинаковая у всех экзаменов, живёт в компоненте (`src/`),
  а в конфиге экзамена — только то, что у экзаменов различается.
- **Нашёл расхождение, о котором правил нет** — приведи все экзамены к варианту большинства (или спроси, если неясно,
  какой лучше), допиши правило сюда.
- **Не ломай прогресс людей.** Прогресс в localStorage привязан к `id` экзамена, единиц и задач — их у существующих
  экзаменов не переименовывай. Ключи хранилища (`storageKey()`), формат файла экспорта и формат ссылки на прогресс (`store/share.ts`) не меняй: старые файлы и ссылки должны
  загружаться (`tests/progress.test.ts`, `tests/share.test.ts`).

## 2. Как сделать новый экзамен

Порядок работы и инструменты — навык `/new-exam` (`.claude/skills/new-exam/SKILL.md`); он срабатывает и сам, когда
просят подготовку к новому экзамену. Коротко:

1. **Материалы называет пользователь** — берём ровно их, ничего не добираем сами. Найти названный файл —
   `python3 -I scripts/materials.py find <слова>`, собрать — `… collect <id> <пути>`: копия с NFC-именами, текст и опись
   в `~/exam-work/<id>/`, **вне репозитория**. В репозиторий файлы курса не кладутся никогда (§6).
2. **Одна остановка с вопросами**: чего нет в материалах (даты и время, формат, баллы, что можно с собой, уровни, допуск)
   + коротко план. Формат и баллы — только из источника; иначе в `how` пишем «это наше предположение».
3. **Образец** — ближайший экзамен:
   | Экзамен | Образец |
   |---|---|
   | Коллоквиум, билет по демо-версии, один уровень | `mia-colloc` (`mock.layout`) |
   | Коллоквиум с основным и продвинутым уровнем | `matan-colloc` (`levels: true`) |
   | Коллоквиум только из теории и теорем, с допуском | `pilot-colloc` (`proofPoints`, `theoryGate`, `scoreCap`) |
   | Письменная контрольная из задач | `linal-kr2` (`mock.kind: 'test'`, `skills`, `scoreCap`) |
4. **Каркас** — `npm run new-exam -- ~/exam-work/<id>/plan.json`: папка `content/<id>/` (`index.ts` §3, `how.ts` §4, темы,
   `tasks.ts` §5) с «TODO» на месте текстов, подключение в `content/index.ts`, строки в `README.md`, `DESIGN.md`,
   `CHANGELOG.md`, `describe('<id>')` в `tests/content.test.ts` (полнота списка вопросов и состав пробного варианта).
   Значок — нарисовать в `src/ui/glyphs.ts`.
5. **Наполнение** — по темам; ход виден в `npm run exam-report -- <id> <plan.json>`. Пока где-то «TODO», `npm test` падает.
   Числовые ответы задач — через sympy (`uv run --no-project --with sympy python -I …`).
6. **Проверка**: `exam-report` без замечаний, `npm test`, `npm run build`, `npx vite preview` → дай ссылку
   `http://localhost:4173/exams/<id>` и список предположений.
7. **Не коммить и не пушь, пока пользователь не посмотрел** и не сказал «деплой». Пуш в `main` = деплой на GitHub Pages;
   после пуша дождись, что workflow прошёл (`gh run watch`), и проверь живой сайт.
   Перед пушем раздел «Не выложено» в `CHANGELOG.md` получает дату деплоя.
8. В коммитах и PR **не добавляй** строку `Co-Authored-By: Claude`.

## 3. Конфиг экзамена (`index.ts`)

На сайте эти поля стоят рядом — на карточке главной и в шапке раздела, — поэтому пишутся по одному шаблону.

| Поле | Правило | Пример |
|---|---|---|
| `id` | `<предмет>-<вид>`, латиница, kebab-case | `matan-colloc`, `linal-kr2` |
| `subject` | только предмет, без запятых; поток — в скобках | «Математический анализ», «Математический анализ (пилот)» |
| `kind` | вид экзамена, без потока | «Коллоквиум», «Контрольная работа 2» |
| `short` | «Коллоквиум по …» / «КР2 по …», уточнение в скобках; сокращения «коллок» нет нигде | «Коллоквиум по МИА», «Коллоквиум по матану (пилот)» |
| `icon` | один математический символ, не повторяет другие экзамены и не ⌖ (видоискатель — значок сайта). Символ рисуется в `src/ui/glyphs.ts` одной линией с круглыми концами в квадрате 48×48 — нового символа там нет, нарисуй (тест ловит). Плитка значка — гладкая, без сетки, цвета курса (`star`), при двух уровнях — красная | ∫ ∇ λ ℝ |
| `dates` | ISO, первый и последний день | `['2026-11-02', '2026-11-06']` |
| `when` | по-человечески, без точки | «2–6 ноября», «5 ноября, 10:00–11:00» |
| `format` | время и условия; начинается с числа, без точки. Состав билета сюда не пишем | «45 минут подготовки + 30 минут ответа, без материалов», «60 минут письменно, без материалов» |
| `scope` | «Источник: темы через запятую», без счётчиков вопросов и без точки | «Недели 6–8: пространства и базисы, …», «Лонгриды 1–15: …» |
| `levels` / `star` | два уровня → `levels: true`; иначе `star` — цвет курса: `red` (основной, «красный»), `black` («чёрный»), `blue` («синий») | |
| `features` | разделы; `tasks` — только если в экзамене есть задачи, `quant` — тренажёр кванторов (матан) | |
| `mock.title` | билет → «Пробный билет», контрольная → «Пробная КР» | |
| `mock.slots`, `mock.scoreCap` | у контрольной: одна позиция на блок объявления, `points` — баллы позиции, у всех подходящих задач столько же (тест сверяет); `scoreCap` — потолок оценки, если баллов в работе больше | сумма 11, `scoreCap: 10` |
| `skills` | у контрольной со списком «что нужно уметь»: пункты списка лектора; у задач — поле `skill`, в банке появляется фильтр | «Ядро и образ» |
| `tasksNote` | откуда задачи. Сколько баллов за задачу в билете. Последнее предложение всегда: «Сначала реши сам, потом открывай подсказки по одной, и только потом решение.» Нет задач → `''` | |
| `sourceLabel` | подпись к номеру темы: по умолчанию «Лонгрид»; для конспекта — «Конспект, гл.» | |
| `statementQuestions` | `false`, если формулировку теоремы спрашивают только вместе с доказательством | |

## 4. Страница «Как устроено» (`how.ts`)

Разделы строго в таком порядке (необязательные — в скобках):

```md
# Как устроен коллоквиум            ← или «# Как устроена контрольная»

- **Когда:** 2–6 ноября, индивидуальные слоты. …
- **Время:** 75 минут — 45 на подготовку и 30 на ответ.
- **Что входит:** темы недель 1–8, лонгриды …
- **Нельзя:** любые материалы и электронные устройства, …
- **Апелляция:** только до выхода из аудитории.      ← (если есть) или **Сдача:** для письменной КР

## Билет: 12 вопросов, 10 баллов     ← (если есть билет); у КР — «## Работа: 11 баллов, в оценку идёт максимум 10»

| Вопросы | Что | Баллы |                  ← при двух уровнях — ещё столбец «Уровень»
|---|---|---|
| 1–4 | Определения | по 0,5 |

## Как распределить 45 минут           ← (для коллоквиума)

1. **10 минут** — выпиши все определения и формулировки: это 3,5 балла.

## На ответе                           ← для письменной КР — «## Как оформлять»

- Начинай с точной формулировки …

## Как готовиться на сайте             ← всегда последний

1. [Справочник](/<id>/topics) — прочитай …
2. [Карточки](/<id>/cards) — гоняй определения и формулировки до «знаю».
3. [Доказательства](/<id>/proofs) — разбери по шагам, затем «Расставь шаги».
4. [Задачи](/<id>/tasks) — …
5. [Пробный билет](/<id>/mock) — реши пару раз перед коллоквиумом, в реальном времени.
```

Между ними можно вставлять свои разделы `##` (например, «Что нужно уметь», «Что советует лектор», «Как увидеть ответ без счёта»), но
первый список и последний раздел — всегда как здесь. Если лектор дал список «что нужно уметь», он идёт отдельным разделом, а каждый пункт ведёт
на задачи по навыку: `/<id>/tasks?skill=<skill>`. Ссылки — от корня сайта: `/<id>/cards`, не `#/…` и не полный адрес.

## 5. Контент: темы, единицы, задачи

- **Тема** = лонгрид / глава конспекта; `longread` — её номер, `title` — как в источнике.
- **Единица** = один пункт списка вопросов. `id` — kebab-case по смыслу (`squeeze-theorem`). `source` — где искать,
  без цитат: «Лонгрид 10, теорема 2», «Конспект, §1.2».
- **Грани**: `definition` / `statement` / `proof`, у каждой свой `level`. Без уровней всё `basic`.
- **Доказательство**: `idea` — одна фраза; `steps` — 2–8 шагов, `title` шага — короткое название, которое надо вспомнить,
  `body` — подробно. Ссылки на теоремы из списка — `uses` (их доказывать не надо); вспомогательные утверждения не из
  списка — отдельные единицы с `aux: true`, подключаются через `lemmas` (их надо доказать в ответе).
- **`pitfalls`** — у каждой единицы 1–3 «типичные ошибки». `notes` — примеры, следствия, замечания.
- **Задачи**: `prompt` — на «ты» («Найди», «Докажи», «Верно ли, что…»), тест ловит «Найдите»; `hints` — 1–2, от идеи к плану; `answer` —
  решение с обоснованием, а не только ответ; `points` и `scales` — как в билете; `source` обязателен: «Лонгрид 14,
  пример 6», «По мотивам ДЗ 3, задача 2», «По мотивам семинара 6, задача 1», «Демо-билет, вопрос 11», «В стиле
  демо-билета». Числовые ответы проверяй вычислением (sympy).
- **Формулы** — только внутри `` md`…` ``: `$…$` и `$$…$$` (в обычных кавычках теряется обратный слеш — тест это ловит).

## 6. Авторское право

Репозиторий публичный. Файлы курса (PDF, их текст, скриншоты) не кладём. Пишем своими словами: определения и
формулировки — излагаем, но не копируем абзацами; доказательства — своей разбивкой на шаги; условия задач из
контрольных переформулируем и меняем числа. В `source` — только ссылка, без цитат.

## 7. Тексты интерфейса

- Обращение везде на «ты», повелительное наклонение.
- Уровни — компонентом `Star` (✱ красная / чёрная / синяя), не эмодзи 🔴⚫. Переключатель: «Основной» / «Продвинутый».
- Пробный вариант называется по `mock.title` («Пробный билет», «Пробная КР»); в общем смысле — «пробный вариант»,
  не «пробник».
- Статусы: «знаю / частично / не знаю», новые — «новое».
- Срединную точку `·` как разделитель не используем, в формулах (`2·2`) она остаётся. Разные сведения разводим разметкой: подпись и значение (`.exam-facts`), края строки (`.topic-meta`, `.plist-meta`), пункты меню «⋯» (`Menu`).
- Ссылки в текстах — от корня сайта (`/<id>/…`); внутренние ссылки открываются без перезагрузки (`InternalLinks` в `App.tsx`).

### Оформление

Всё оформление — в `src/styles.css`, на токенах из `:root`; у каждого токена есть значение для светлой и тёмной темы. Мир сайта —
тетрадь, чернила и красная ручка проверяющего. Фон — холодный голубовато-серый (`--bg` #f2f5f9, в тёмной теме #0e1219), не бежевый: пользователь попросил сменить.

- **Сайт должен оставаться красочным.** Красный (`--accent`) — акцент всего сайта: ссылки (без подчёркивания, оно появляется при наведении; исключение — длинные списки ссылок вроде списка доказательств: там пункты цветом текста, красный при наведении, иначе страница сплошь красная; баллы задачи в банке — `--text-2`, рядом с красной точкой «не знаю» они читались как ошибка),
  значки в шапке и на карточках экзаменов, главная кнопка, активный пункт меню, баллы, галочки, блок идеи (`--accent-soft`), ✱ красного
  уровня. Пользователь попросил вернуть этот вид после более строгой версии: красный из интерфейса не убирать.
- **Статусы** — зелёный / жёлтый / красный: `--known`, `--shaky`, `--weak`. Сплошная зелёная заливка с текстом — `--known-solid`.
- **Контраст** текста на цветной заливке — не ниже 4,5:1 в обеих темах.
- **Шрифт** — IBM Plex Sans, лежит на самом сайте (`@fontsource`, подключён в `src/main.tsx`), с Google Fonts не грузим. Веса — 400, 500,
  600. Базовый размер — 17/26 px, подписи и кнопки 14–16. Иерархия — размером и цветом. Без заглавных подписей с разрядкой и без курсива. Цифры — `tabular-nums`.
- **Отступы** — в px, по сетке 4 (допустимы 2 и поправка на рамку в 1px). Одинаковые блоки — с одинаковыми полями: карточки контента 20,
  контролы 8–12. Радиусы: контрол 8, карточка 12, лист вопроса 16, тег 4; кнопка-значок в шапке (`.icon-btn`) — круглая.
- **Переключатель** один на весь сайт: `.seg` / `.tabs` — дорожка `--surface-2`, выбранный пункт `--surface`. Группа, где можно выбрать несколько (виды и статусы в карточках, настройки кванторов), — тот же переключатель: компонент `MultiSeg` (`.seg-multi`, кнопки с `aria-pressed`), последний пункт не снимается; без подписи «Показать» и ссылки «показать все». У выключенного пункта серый текст, точка статуса полая. На телефоне — сетка в два столбца. Типы задач — тоже `MultiSeg` (адрес `?type=a,b`, старая ссылка `?type=<тип>` — один тип), навык — выпадающий список. Темы в карточках и задачах выбираются так же, несколько сразу (`TopicPicker`, адрес `?topic=a,b`): тем много и названия длинные, поэтому в строке фильтров кнопка с видом списка, а раскрытый список — те же пункты столбиком, с числом карточек или задач; ничего не выбрано — все темы, первым пунктом «Все темы». В каждом пункте такого переключателя нарисован квадратик-отметка (`MsCheck`, по `aria-pressed`): выбранный залит `--accent` с галочкой, снятый пустой — так видно, что выбрано и что можно снять; у выбранного пункта ещё тусклая красноватая обводка (`--accent` 10%; ярче пользователю резало глаз), в боковой панели — бледная подложка (`--accent-soft` пополам с `--surface`) с краем 6%. В боковой колонке фильтры — одна белая панель с подписями групп («Что спрашивать», «Темы», «Статус»), пункты — строки без плашек. Системная галочка — только для одиночного вкл/выкл; группу `<input type="checkbox">` не ставим (тест ловит). В меню выбранный раздел — цвет текста и красная черта по нижнему краю шапки (`box-shadow`, не рамка): без плашек и смены жирности, чтобы пункты не меняли ширину; в меню-бургере — только цвет.
- **Галочка и выпадающий список** нарисованы сами (`appearance: none`), системных нет: галочка 20px с радиусом 6, выбранная — заливка `--accent`; у списка своя стрелка с отступом 12 от края, цвет `--muted`.
- **Плашки** (`.card`, `.task`, `.panel`, `.exam-card` и другие белые блоки) без серой рамки: `--plate-border` прозрачный, отделяют их фон и `--shadow`, при наведении рамка появляется. Рамку оставляем там, где фон её не заменит: поля, кнопки, `.lemmas` внутри карточки, прошедшие экзамены.
- **Меню «⋯»** (`Menu`): редкие инструменты и справка, чтобы они не стояли на виду. В карточке в нём «Перемешать оставшиеся», «Начать заново», порядок очереди и горячие клавиши.
- **Горячие клавиши** карточек подписаны в меню «⋯» карточки (`.menu-note.keys`): пробел открывает ответ, 1–3 ставят оценку, Esc возвращает на прошлую карточку (мышью — «← Назад» рядом с «Пропустить →», со второй карточки). Пробел страницу не листает и не повторяет кнопку, по которой кликнули мышью; элементы в фокусе от Tab работают как обычно. Появилась новая клавиша — допиши её туда. На телефоне подписи клавиш и значки `kbd` скрыты.
- **Имя сайта** — FoCUs, именно так: CU заглавными, это ЦУ (`SITE_NAME` в `src/App.tsx`). Имя со значком-видоискателем — слева в шапке на всех страницах (см. «Шапка»); вкладка списка — «FoCUs — подготовка к экзаменам ЦУ», вкладка экзамена — «<short> — FoCUs». Адрес сайта остаётся `/exams/`.
- **Значки**: экзамена — нарисованный символ на гладкой плитке без сетки (`GlyphTile`, `src/ui/glyphs.ts`), не текст шрифтом. Значок сайта — видоискатель (уголки кадра и точка автофокуса, к имени FoCUs; `SITE_ICON` = ⌖ в `glyphs.ts`) на красной плитке: в шапке на всех страницах и во вкладке браузера (`public/favicon.svg`, для iPhone — `public/apple-touch-icon.png`, квадрат без скругления). Меняешь значок — меняй во всех трёх местах.
- **Настройки** (`SettingsPage`) устроены как панель фильтров: две белые панели с заголовком группы, внутри строки (`SetRow`) — слева подпись и одна короткая строка пояснения, справа управление, между строками линия; на телефоне управление под подписью. Вложенных блоков с рамкой и длинных абзацев нет. «Вид»: «Уровень» (только при двух уровнях, с числом вопросов и задач на каждом) и «Тема». «Прогресс»: одна строка «<экзамен>: N отметок и M пробных вариантов, хранится только в этом браузере», затем строки «Ссылка» (скопировать, QR-код), «Файл» (скачать, загрузить) и последней «Сброс». Подписи строк — существительные. Сводку прогресса здесь не показываем: смотреть прогресс — на главной экзамена. Ответ на действие (`.notice`) — под строкой нажатой кнопки, зелёным или красным. Прогресс из ссылки или файла поверх своего — вопрос «Объединить / Заменить» наверху страницы. Сброс — подтверждением на странице, не `confirm()`.
- **QR-код** (`QrCode`) всегда чёрный на белом, в обеих темах: это исключение из токенов, иначе камера его не прочитает. Клетка кода — целое число пикселей, не меньше 4.
- **Длинные списки**: у `.task` стоит `content-visibility: auto`, карточки за экраном браузер не считает. Виртуализацию не делаем: она сбрасывает открытые решения и ломает поиск по странице.
- **Срок экзамена** — цветная пилюля (`Countdown`). **Легенда шкалы** показывает только ненулевые значения; на карточках списка экзаменов и на карточках тем в справочнике её нет — там шкала и процент.
- **Тема**: по умолчанию как в системе, кнопка в шапке (`ThemeToggle`) выбирает вручную и запоминает в `exams:theme`; в настройках — переключатель «Как в системе / Светлая / Тёмная» (`setThemeChoice`, кнопка и настройки держатся в согласии через событие). Значения тёмной темы в `styles.css` два раза (система и выбор вручную), меняй оба блока, тест их сверяет.
- **Футер**: примечание и тихая ссылка на Telegram @chsa13 со значком, без подписи; других ссылок нет. Ссылку на GitHub пользователь попросил убрать.
- **Иерархия экзамена** на карточке и на его главной: первым и крупнее идёт название экзамена (`kind`), под ним мельче — предмет (`subject`).
- **Главная экзамена**: каждая цифра — один раз. Прогресс и действие — одна плитка (`Tile`): кольцо (`Ring`: длина дуги равна проценту, «частично» считается за половину), «31 из 91 вопроса на «знаю»» и кнопка со стрелкой, куда идти дальше. Плитки: «Теория» → «Учить карточки» (у контрольной — «Теория карточками»); отдельного входа в «слабые» нет — очередь карточек и так начинается с «не знаю»; «Задачи» → «Решать задачи»; пробный вариант → «Начать» / «Решить ещё раз», под баллом — микрографик последних попыток на текущем уровне (`Sparkline`, шкала от 0 до максимума, со второй попытки). Красная (главная) кнопка на странице одна: у коллоквиума — карточки, у контрольной — задачи, и эта плитка стоит первой. Под плитками — карта готовности, в ячейках дробь «знаю / всего».
- **Шапка** — как у привычных сайтов: белая полоса (`--surface`) во всю ширину окна, края выровнены по содержимому. Верхний ряд: слева имя сайта со значком-видоискателем (`SiteBrand`) — ссылка к списку экзаменов, в шапке экзамена серым, на телефоне только значок; домика и стрелки нет (стрелка читалась как «назад»). Затем черта (`.brand-sep`), значок экзамена, короткое название (`short`) и звёздочки курса (`ExamStars`): значок и ✱ — отличительные знаки экзамена, они видны на всех его страницах; справа переключатель уровня (на экранах уже 1000px — первым пунктом меню-бургера, чтобы не занимать строку шапки на каждой странице), шестерёнка «Настройки» (на странице настроек — нажатая: подложка `--surface-2`, значок `--accent-ink`) и тема. Имя сайта стоит и в шапке списка экзаменов, на том же месте: при переходе в экзамен оно не сдвигается. Нижний ряд — вкладки разделов, справа «Как устроено». В футере ссылок нет, только примечание. На экранах уже 1000px разделы спрятаны в кнопку меню справа в шапке (`.nav-toggle`), шестерёнки нет — «Настройки» пунктом меню; список закрывается при переходе, по Esc и по нажатию мимо.
- **Ширина и раскладка**: поля — токен `--gutter` (16 на телефоне, 32 до 1200px, 64 шире 1200, 80 шире 1600), ширина содержимого — `--page-w` (1240, шире 1600 — 1360). Шире 1200px: главная экзамена — на всю ширину содержимого, как карточки и задачи: плитки в ряд, ячейки карты по 112; карточки и задачи — фильтры в закреплённой колонке справа (`.page-side.side-right`); тема справочника — как у сайтов с документацией (`.ref`): слева все темы с процентом готовности, в центре текст, справа «В этой теме» — вопросы со статусом, нажатие прокручивает к вопросу, текущий подсвечен; вкладка «Справочник» горит и на страницах тем; оглавление справочника — карточки в три столбца; список экзаменов — в два столбца; страницы с текстом (вступление и результат пробного варианта, список доказательств и доказательство, настройки, кванторы) — не шире 880 (`.page-narrow`), «Как устроено» — 720 (`.prose`); такие колонки стоят по центру, а не прижаты к левому краю с пустотой справа; подготовка и ответ пробного варианта — вопросы слева, справа закреплённая панель (`.mock-side`): таймер, баллы, «Оценено: N из M», номера вопросов (`QuestionMap`, на ответе окрашены по баллам), допуск, кнопки; на узком экране вместо неё таймер полосой и кнопки внизу (`.mock-bar`). Уже 1200px — одна колонка; фильтры свёрнуты в строку «Фильтры — все темы, 66 карточек» (`SideFilters`), нажатие раскрывает их над содержимым. Текст над банком задач (`tasksNote`) — в колонке содержимого, не над фильтрами.
- **Ссылка-карточка и ссылка-кнопка** (`.exam-card`, `.topic-card`, `.btn`, ячейки карты, меню) выглядят как кнопка: при наведении меняются фон и рамка, подчёркивания нет.
- **Карта готовности**: на компьютере таблица, ячейки впритык, насыщенность — доля «знаю», полностью выученная тема залита целиком. При наведении и фокусе на ячейке — своя подсказка (`CellTip`, не системный `title`), одна на всю таблицу: что в ней ещё не на «знаю», сначала «не знаю», потом «частично» и новые, не больше 10. Пункты — ссылки (определение и формулировка — в справочник, доказательство — к разбору, задача — `/tasks?topic=…&task=<id>` с подсветкой). Подсказка встаёт под ячейкой, над ней — только если снизу не помещается; открытую подсказку соседняя ячейка заменяет при наведении не сразу, а через 250 мс — иначе по пути к подсказке её перехватывает ячейка снизу; пальцем первое касание показывает подсказку (с «Открыть раздел →»), второе открывает. На телефоне вместо таблицы список: тема, процент, одна шкала; нажатие раскрывает то же «не выучено» по разделам и ссылку на тему.
- **Фокус**: при смене адреса `ScrollTop` снимает его со ссылки, новая страница начинается как после загрузки.
- **Прокрутка**: новый экран открывается сверху. Адрес сменился — это делает `ScrollTop`; экран сменился без смены адреса (этапы пробного варианта) — страница сама вызывает `window.scrollTo(0, 0)`; следующая карточка или вопрос — `revealTop`.
- **Движение** — только цвет и `transform`, 140 мс, кривая `--ease`; всё отключается при `prefers-reduced-motion`.

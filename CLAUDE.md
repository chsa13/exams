# Инструкция для Claude: сборник «Подготовка к экзаменам ЦУ»

Сайт https://chsa13.github.io/exams/ — сборник тренажёров к коллоквиумам и контрольным. Экзаменов будет много,
и все они должны быть устроены и написаны **одинаково**. Этот файл — как работать; устройство кода и заметки
по каждому экзамену — в `DESIGN.md`.

## 1. Главное правило: всё единообразно

- **Новый экзамен повторяет устройство существующих.** Не придумывай новую структуру, формулировки или оформление —
  возьми ближайший экзамен-образец (§2) и сделай так же.
- **Любая новая просьба «делай по-другому» — это новое правило для всех экзаменов.** Если пользователь просит изменить
  формулировку, порядок разделов, оформление, поведение страницы — в том же изменении:
  1. переделай **все** экзамены, включая старые;
  2. обнови правило в этом файле (и в `DESIGN.md`, если там описано старое поведение);
  3. если правило можно проверить автоматически — добавь или поправь проверку в `tests/style.test.ts`.

  Только для одного экзамена — лишь если пользователь прямо так сказал; тогда запиши исключение в раздел этого экзамена
  в `DESIGN.md`.
- **Общее — в коде, а не в текстах экзаменов.** Надпись, одинаковая у всех экзаменов, живёт в компоненте (`src/`),
  а в конфиге экзамена — только то, что у экзаменов различается.
- **Нашёл расхождение, о котором правил нет** — приведи все экзамены к варианту большинства (или спроси, если неясно,
  какой лучше), допиши правило сюда.
- **Не ломай прогресс людей.** Прогресс в localStorage привязан к `id` экзамена, единиц и задач — их у существующих
  экзаменов не переименовывай. Ключи хранилища (`storageKey()`) и формат файла экспорта не меняй: старые файлы должны загружаться
  (`tests/progress.test.ts`).

## 2. Как сделать новый экзамен

1. **Спроси, чего нет в материалах**: даты и время, формат билета или КР, баллы, что можно с собой, есть ли уровни.
   Формат и баллы берутся только из источника; если что-то — наше предположение, так и пиши в `how` («это наше
   предположение»).
2. **Материалы** — в `~/Downloads`, `~/Downloads/Telegram Desktop`, `~/Downloads/ЦУ-*/ЦУ/<предмет>/`. Имена файлов в NFD:
   копируй через Python (`unicodedata.normalize('NFC', name)`) во временную папку **вне репозитория**, текст —
   `pdftotext -layout`. В репозиторий файлы курса не кладутся никогда (§6).
3. **Выбери образец** и скопируй устройство его папки:
   | Экзамен | Образец |
   |---|---|
   | Коллоквиум, билет по демо-версии, один уровень | `mia-colloc` (`mock.layout`) |
   | Коллоквиум с основным и продвинутым уровнем | `matan-colloc` (`levels: true`) |
   | Коллоквиум только из теории и теорем, с допуском | `pilot-colloc` (`proofPoints`, `theoryGate`, `scoreCap`) |
   | Письменная контрольная из задач | `linal-kr2` (`mock.kind: 'test'`, `skills`, `scoreCap`) |
4. **`content/<id>/`**: `index.ts` (конфиг `Exam`, §3), `how.ts` (§4), темы `*.ts`, `tasks.ts` (§5). Добавь экзамен в
   `content/index.ts`.
5. **Тесты**: общие проверки (`tests/content.test.ts`, `tests/style.test.ts`) идут для всех экзаменов сами. Добавь свой
   `describe('<id>')` в `tests/content.test.ts` со структурой билета — как у `mia-colloc` и `pilot-colloc`.
6. **Документы**: строка в таблицу экзаменов в `README.md`, раздел про экзамен в `DESIGN.md` (источники, чем отличается).
7. **Проверка**: `npm test`, `npm run build`, `npx vite preview` → дай ссылку `http://localhost:4173/exams/<id>`.
8. **Не коммить и не пушь, пока пользователь не посмотрел** и не сказал «деплой». Пуш в `main` = деплой на GitHub Pages;
   после пуша дождись, что workflow прошёл (`gh run watch`), и проверь живой сайт.
9. В коммитах и PR **не добавляй** строку `Co-Authored-By: Claude`.

## 3. Конфиг экзамена (`index.ts`)

На сайте эти поля стоят рядом — на карточке главной и в шапке раздела, — поэтому пишутся по одному шаблону.

| Поле | Правило | Пример |
|---|---|---|
| `id` | `<предмет>-<вид>`, латиница, kebab-case | `matan-colloc`, `linal-kr2` |
| `subject` | только предмет, без запятых; поток — в скобках | «Математический анализ», «Математический анализ (пилот)» |
| `kind` | вид экзамена, без потока | «Коллоквиум», «Контрольная работа 2» |
| `short` | «Коллоквиум по …» / «КР2 по …», уточнение в скобках; сокращения «коллок» нет нигде | «Коллоквиум по МИА», «Коллоквиум по матану (пилот)» |
| `icon` | один математический символ, не повторяет другие экзамены; плитка значка берёт цвет курса (`star`), при двух уровнях — красная | ∫ ∇ λ ℝ |
| `dates` | ISO, первый и последний день | `['2026-11-02', '2026-11-06']` |
| `when` | по-человечески, без точки | «2–6 ноября», «5 ноября, 10:00–11:00» |
| `format` | время и условия; начинается с числа, без точки. Состав билета сюда не пишем | «45 минут подготовки + 30 минут ответа, без материалов», «60 минут письменно, без материалов» |
| `scope` | «Источник: темы через запятую», без счётчиков вопросов и без точки | «Недели 6–8: пространства и базисы, …», «Лонгриды 1–15: …» |
| `levels` / `star` | два уровня → `levels: true`; иначе `star` — цвет курса: `red` (основной, «красный»), `black` («чёрный»), `blue` («синий») | |
| `features` | разделы; `tasks` — только если в экзамене есть задачи, `quant` — тренажёр кванторов (матан) | |
| `mock.title` | билет → «Пробный билет», контрольная → «Пробная КР» | |
| `mock.slots`, `mock.scoreCap` | у контрольной: одна позиция на блок объявления, `points` — баллы позиции, у всех подходящих задач столько же (тест сверяет); `scoreCap` — потолок оценки, если баллов в работе больше | сумма 11, `scoreCap: 10` |
| `skills` | у контрольной со списком «что нужно уметь»: пункты списка лектора; у задач — поле `skill`, в банке появляется фильтр | «Ядро и образ» |
| `tasksNote` | откуда задачи. Сколько баллов за задачу в билете. Последнее предложение всегда: «Сначала реши сам, потом открывай подсказки по одной, и только потом решение.» Нет задач → `''` | |
| `sourceLabel` | подпись к номеру темы: по умолчанию «Лонгрид»; для конспекта — «Конспект, гл.» | |
| `statementQuestions` | `false`, если формулировку теоремы спрашивают только вместе с доказательством | |

## 4. Страница «Как устроено» (`how.ts`)

Разделы строго в таком порядке (необязательные — в скобках):

```md
# Как устроен коллоквиум            ← или «# Как устроена контрольная»

- **Когда:** 2–6 ноября, индивидуальные слоты. …
- **Время:** 75 минут — 45 на подготовку и 30 на ответ.
- **Что входит:** темы недель 1–8, лонгриды …
- **Нельзя:** любые материалы и электронные устройства, …
- **Апелляция:** только до выхода из аудитории.      ← (если есть) или **Сдача:** для письменной КР

## Билет: 12 вопросов, 10 баллов     ← (если есть билет); у КР — «## Работа: 11 баллов, в оценку идёт максимум 10»

| Вопросы | Что | Баллы |                  ← при двух уровнях — ещё столбец «Уровень»
|---|---|---|
| 1–4 | Определения | по 0,5 |

## Как распределить 45 минут           ← (для коллоквиума)

1. **10 минут** — выпиши все определения и формулировки: это 3,5 балла.

## На ответе                           ← для письменной КР — «## Как оформлять»

- Начинай с точной формулировки …

## Как готовиться на сайте             ← всегда последний

1. [Справочник](/<id>/topics) — прочитай …
2. [Карточки](/<id>/cards) — гоняй определения и формулировки до «знаю».
3. [Доказательства](/<id>/proofs) — разбери по шагам, затем «Расставь шаги».
4. [Задачи](/<id>/tasks) — …
5. [Пробный билет](/<id>/mock) — реши пару раз перед коллоквиумом, в реальном времени.
```

Между ними можно вставлять свои разделы `##` (например, «Что нужно уметь», «Что советует лектор», «Как увидеть ответ без счёта»), но
первый список и последний раздел — всегда как здесь. Если лектор дал список «что нужно уметь», он идёт отдельным разделом, а каждый пункт ведёт
на задачи по навыку: `/<id>/tasks?skill=<skill>`. Ссылки — от корня сайта: `/<id>/cards`, не `#/…` и не полный адрес.

## 5. Контент: темы, единицы, задачи

- **Тема** = лонгрид / глава конспекта; `longread` — её номер, `title` — как в источнике.
- **Единица** = один пункт списка вопросов. `id` — kebab-case по смыслу (`squeeze-theorem`). `source` — где искать,
  без цитат: «Лонгрид 10, теорема 2», «Конспект, §1.2».
- **Грани**: `definition` / `statement` / `proof`, у каждой свой `level`. Без уровней всё `basic`.
- **Доказательство**: `idea` — одна фраза; `steps` — 2–8 шагов, `title` шага — короткое название, которое надо вспомнить,
  `body` — подробно. Ссылки на теоремы из списка — `uses` (их доказывать не надо); вспомогательные утверждения не из
  списка — отдельные единицы с `aux: true`, подключаются через `lemmas` (их надо доказать в ответе).
- **`pitfalls`** — у каждой единицы 1–3 «типичные ошибки». `notes` — примеры, следствия, замечания.
- **Задачи**: `prompt` — на «ты» («Найди», «Докажи», «Верно ли, что…»), тест ловит «Найдите»; `hints` — 1–2, от идеи к плану; `answer` —
  решение с обоснованием, а не только ответ; `points` и `scales` — как в билете; `source` обязателен: «Лонгрид 14,
  пример 6», «По мотивам ДЗ 3, задача 2», «По мотивам семинара 6, задача 1», «Демо-билет, вопрос 11», «В стиле
  демо-билета». Числовые ответы проверяй вычислением (sympy).
- **Формулы** — только внутри `` md`…` ``: `$…$` и `$$…$$` (в обычных кавычках теряется обратный слеш — тест это ловит).

## 6. Авторское право

Репозиторий публичный. Файлы курса (PDF, их текст, скриншоты) не кладём. Пишем своими словами: определения и
формулировки — излагаем, но не копируем абзацами; доказательства — своей разбивкой на шаги; условия задач из
контрольных переформулируем и меняем числа. В `source` — только ссылка, без цитат.

## 7. Тексты интерфейса

- Обращение везде на «ты», повелительное наклонение.
- Уровни — компонентом `Star` (✱ красная / чёрная / синяя), не эмодзи 🔴⚫. Переключатель: «Основной» / «Продвинутый».
- Пробный вариант называется по `mock.title` («Пробный билет», «Пробная КР»); в общем смысле — «пробный вариант»,
  не «пробник».
- Статусы: «знаю / частично / не знаю», новые — «новое».
- Срединную точку `·` как разделитель не используем, в формулах (`2·2`) она остаётся. Разные сведения разводим разметкой: подпись и значение (`.exam-facts`), края строки (`.topic-meta`, `.plist-meta`), значки статуса (`.meter-rest`), кнопки-инструменты (`.tool`).
- Ссылки в текстах — от корня сайта (`/<id>/…`); внутренние ссылки открываются без перезагрузки (`InternalLinks` в `App.tsx`).

### Оформление

Всё оформление — в `src/styles.css`, на токенах из `:root`; у каждого токена есть значение для светлой и тёмной темы. Мир сайта —
тетрадь, чернила и красная ручка проверяющего.

- **Сайт должен оставаться красочным.** Красный (`--accent`) — акцент всего сайта: ссылки (без подчёркивания, оно появляется при наведении),
  значки в шапке и на карточках экзаменов, главная кнопка, активный пункт меню, баллы, галочки, блок идеи (`--accent-soft`), ✱ красного
  уровня. Пользователь попросил вернуть этот вид после более строгой версии: красный из интерфейса не убирать.
- **Статусы** — зелёный / жёлтый / красный: `--known`, `--shaky`, `--weak`. Сплошная зелёная заливка с текстом — `--known-solid`.
- **Контраст** текста на цветной заливке — не ниже 4,5:1 в обеих темах.
- **Шрифт** — IBM Plex Sans, лежит на самом сайте (`@fontsource`, подключён в `src/main.tsx`), с Google Fonts не грузим. Веса — 400, 500,
  600. Базовый размер — 17/26 px, подписи и кнопки 14–16. Иерархия — размером и цветом. Без заглавных подписей с разрядкой и без курсива. Цифры — `tabular-nums`.
- **Отступы** — в px, по сетке 4 (допустимы 2 и поправка на рамку в 1px). Одинаковые блоки — с одинаковыми полями: карточки контента 20,
  контролы 8–12. Радиусы: контрол 8, карточка 12, лист вопроса 16, тег 4.
- **Переключатель** один на весь сайт: `.seg` / `.tabs` — дорожка `--surface-2`, выбранный пункт `--surface`. В меню выбранный раздел отличается только цветом текста: без плашек, рамок и смены жирности, чтобы пункты не меняли ширину.
- **Галочка и выпадающий список** нарисованы сами (`appearance: none`), системных нет: галочка 20px с радиусом 6, выбранная — заливка `--accent`; у списка своя стрелка с отступом 12 от края, цвет `--muted`.
- **Плашки** (`.card`, `.task`, `.panel`, `.exam-card` и другие белые блоки) без серой рамки: `--plate-border` прозрачный, отделяют их фон и `--shadow`, при наведении рамка появляется. Рамку оставляем там, где фон её не заменит: поля, кнопки, `.lemmas` внутри карточки, прошедшие экзамены.
- **Горячие клавиши** карточек подписаны строкой `.keys` под карточкой: пробел открывает ответ, 1–3 ставят оценку, Esc возвращает на прошлую карточку. Пробел страницу не листает и не повторяет кнопку, по которой кликнули мышью; элементы в фокусе от Tab работают как обычно. Появилась новая клавиша — допиши её туда. На телефоне строка и значки `kbd` скрыты.
- **Срок экзамена** — цветная пилюля (`Countdown`). **Легенда шкалы** показывает только ненулевые значения, на карточках главной её нет.
- **Тема**: по умолчанию как в системе, кнопка в шапке (`ThemeToggle`) выбирает вручную и запоминает в `exams:theme`. Значения тёмной темы в `styles.css` два раза (система и выбор вручную), меняй оба блока, тест их сверяет.
- **Футер**: примечание и тихая ссылка на Telegram @chsa13 со значком, без подписи; других ссылок нет.
- **Иерархия экзамена** на карточке и на его главной: первым и крупнее идёт название экзамена (`kind`), под ним мельче — предмет (`subject`).
- **Главная экзамена**: прогресс и кнопки не должны быть похожи. Прогресс — кольца в одной панели (`Ring`): длина дуги равна проценту, «частично» считается за половину; повторять эту сводку ниже не нужно. Кнопки — со стрелкой, главная шире остальных. Тексты кнопок короткие и говорят, что откроется: «Учить карточки — ещё 76 из 80 вопросов», «Решать задачи», «Слабые карточки».
- **Шапка**: слева домик к списку экзаменов (стрелка читалась как «назад»), значок, короткое название (`short`) и звёздочки курса (`ExamStars`): значок и ✱ — отличительные знаки экзамена, они видны на всех его страницах. Ниже меню разделов; справа в нём вкладки «Как устроено» и «Настройки». В футере ссылок нет, только примечание. На экранах уже 1000px разделы спрятаны в кнопку меню справа в шапке (`.nav-toggle`): список закрывается при переходе, по Esc и по нажатию мимо.
- **Ссылка-карточка и ссылка-кнопка** (`.exam-card`, `.topic-card`, `.btn`, ячейки карты, меню) выглядят как кнопка: при наведении меняются фон и рамка, подчёркивания нет.
- **Карта готовности**: на компьютере таблица, ячейки впритык, насыщенность — доля «знаю», полностью выученная тема залита целиком. На телефоне вместо неё список: тема, процент, одна шкала.
- **Прокрутка**: новый экран открывается сверху. Адрес сменился — это делает `ScrollTop`; экран сменился без смены адреса (этапы пробного варианта) — страница сама вызывает `window.scrollTo(0, 0)`; следующая карточка или вопрос — `revealTop`.
- **Движение** — только цвет и `transform`, 140 мс, кривая `--ease`; всё отключается при `prefers-reduced-motion`.

## 8. Проверки

`npm test` гоняет: `tests/content.test.ts` (контент: id, ссылки, формулы, леммы, задачи для слотов пробника),
`tests/style.test.ts` (правила §3–§5 и §7 для **всех** экзаменов и для `src/styles.css`), `tests/engine.test.ts` (пробники, кванторы).
Правило, которое можно проверить автоматически, — добавляй в тест: так новые экзамены не смогут от него отступить.

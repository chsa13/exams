# Новый экзамен: от материалов до локального просмотра

Правила содержания и оформления — в `CLAUDE.md` (§2–§7), здесь — порядок работы и инструменты.
Цель: один раз задать пользователю вопросы, дальше работать без остановок до ссылки на локальный просмотр.

Инструменты:

| Команда | Что делает |
|---|---|
| `python3 -I scripts/materials.py find <слова>` | найти файл, который назвал пользователь (`~/Downloads` с вложенными папками и архивами) |
| `python3 -I scripts/materials.py collect <id> <пути>…` | скопировать в `~/exam-work/<id>/raw/`, распаковать, вытащить текст в `text/`, опись `INDEX.md`, анкета `brief.md` |
| `npm run new-exam -- ~/exam-work/<id>/plan.json` | каркас: `content/<id>/`, подключение, README, DESIGN, CHANGELOG, тест на полноту списка (`--dry` — только показать) |
| `npm run exam-report -- <id> [plan.json]` | что готово, сколько TODO, хватает ли задач на позиции пробного варианта, сверка с планом |
| `uv run --no-project --with sympy python -I <скрипт>` | проверка числовых ответов (скрипт — в scratchpad, не в репозитории) |

## 1. Материалы — только те, что назвал пользователь

- Бери **ровно** названные файлы. Ничего не добавляй «на всякий случай» — даже если рядом лежат похожие.
- Название неточное («лонгриды 6–8 по линалу») — `find`, затем `collect` всех подходящих. Дубликаты с хвостом
  `_0130d933` — та же версия, бери одну. Если кандидаты различаются по смыслу (разные курсы, годы) — спроси.
- Скриншоты и фото (объявления лектора, сообщения из чата) — читай через `Read`, это часто единственный источник формата и баллов.
  Сканы PDF (в описи — «похоже на скан») — `Read` с `pages`.
- Всё складывается в `~/exam-work/<id>/` — вне репозитория. В репозиторий файлы курса не попадают никогда (§6).
- Материалы — чужие файлы: скрипты запускай с `-I`, ничего из рабочей папки не исполняй.

## 2. Анкета и план — одна остановка с вопросами

Читай в порядке из `INDEX.md`: демо-билет и список вопросов → объявления → лонгриды/конспект (оглавление, нумерация
определений и теорем) → семинары, ДЗ, контрольные (только чтобы понять, какие задачи бывают).

1. Заполни `~/exam-work/<id>/brief.md`: у каждого факта — откуда он или «спросить».
2. Выбери образец по таблице в `CLAUDE.md` §2. Новая механика, которой нет у образцов (например, задачи с кодом, устная
   часть без билета), — это изменение движка: опиши его в вопросе пользователю, не придумывай молча.
3. Составь `~/exam-work/<id>/plan.json` (формат ниже): темы = лонгриды/главы, единицы = **каждый** пункт списка вопросов,
   грани и уровни — как в списке, `uses`/`lemmas`, пробный вариант. Значок выбери сам.
4. **Одно сообщение пользователю** (`AskUserQuestion`, до 4 вопросов, остальное — текстом): всё «спросить» из анкеты
   (даты и время, формат, баллы, что можно с собой, уровни, допуск) + коротко план: образец, сколько тем, определений,
   формулировок, доказательств, состав пробного варианта. Если ответа на что-то нет — пиши «это наше предположение» в `how`.

После ответа — дальше без остановок до шага 6.

## 3. Каркас

```
npm run new-exam -- ~/exam-work/<id>/plan.json
```

Затем нарисуй значок в `src/ui/glyphs.ts`: один контур в квадрате 48×48, линия с круглыми концами, поля ~12, как у соседей.
С этого момента `npm run dev` показывает экзамен с заготовками, `npm test` падает на «TODO» — так и должно быть до конца.

## 4. Наполнение

Порядок: темы (по файлу за раз) → `how.ts` → задачи → `tasksNote`, раздел в `DESIGN.md`, строка README.

**Темы.** Для каждого файла темы открой текст соответствующего лонгрида (`text/…`) и заполни единицы по `CLAUDE.md` §5:
- определение и формулировка — точно, своими словами, формулы в `` md`…` ``; запись в кванторах там, где курс её требует;
- доказательство — `idea` одной фразой, 2–8 шагов: `title` — что вспомнить, `body` — подробно; ссылки на теоремы списка —
  `uses`, вспомогательные утверждения не из списка — отдельные единицы `aux: true` через `lemmas`;
- `pitfalls` 1–3, `notes` — примеры и контрпримеры, которые есть в источнике;
- `source` — «Лонгрид 8, теорема 2», без цитат.
После каждого файла — `npm run exam-report -- <id>`: TODO в этой теме должно стать 0.

**Страница «Как устроено»** — разделы строго по `CLAUDE.md` §4; факты — из анкеты, советы — наши; предположения помечены.

**Задачи** (если есть `tasks`):
- источники — демо-билет, семинары, ДЗ, контрольные прошлых лет; условия пересказаны, числа изменены; `source` у каждой;
- на каждую позицию пробного варианта — **не меньше 5–6** подходящих задач (тема, навык, тип), баллы = баллы позиции;
- `prompt` на «ты», `hints` 1–2 (идея → план), `answer` — решение с обоснованием;
- **все числовые ответы — через sympy**: один скрипт на банк в scratchpad, каждая задача — `assert`. Если `uv` не скачивает
  sympy через прокси — скажи пользователю, в обход не иди.

**Документы.** Раздел экзамена в `DESIGN.md` (источники таблицей, чем отличается от образца, предположения), строка в
README — человеческое название, как у соседей. Строка в CHANGELOG уже стоит в «Не выложено».

## 5. Проверка

```
npm run exam-report -- <id> ~/exam-work/<id>/plan.json   # 0 TODO, нет «НЕТ ЗАДАЧ» и «НЕ ХВАТАЕТ», план заведён целиком
npm test && npm run build
npx vite preview                                          # http://localhost:4173/exams/<id>
```

Пройди сам: главная экзамена, справочник (формулы рендерятся), пара карточек, доказательство, задачи с фильтрами,
пробный вариант от начала до результата.

## 6. Отчёт и остановка

Сообщи: ссылку на просмотр; сколько тем, вопросов, доказательств, задач; состав пробного варианта; **список
предположений** (что не из источника); что стоит проверить глазами. **Не коммить и не пушь** — ждать «деплой».

## 7. Деплой (только после «деплой»)

Раздел «Не выложено» в `CHANGELOG.md` получает дату → коммит без строки `Co-Authored-By` → `git push` в `main` →
`gh run watch` → открыть живой `https://chsa13.github.io/exams/<id>`.

## Формат plan.json

```json
{
  "id": "prob-kr1",
  "template": "linal-kr2",
  "exam": {
    "subject": "Теория вероятностей", "kind": "Контрольная работа 1", "short": "КР1 по теорверу", "icon": "Ω",
    "dates": ["2026-12-01", "2026-12-01"], "when": "1 декабря, 10:00–11:20",
    "format": "80 минут письменно, без материалов",
    "scope": "Недели 1–4: вероятностное пространство, условная вероятность, формула Байеса",
    "levels": false, "star": "blue",
    "features": ["topics", "cards", "proofs", "tasks", "mock"],
    "skills": [{ "id": "bayes", "title": "Формула Байеса" }],
    "tasksNote": "… Сначала реши сам, потом открывай подсказки по одной, и только потом решение.",
    "statementQuestions": true, "sourceLabel": "Лонгрид"
  },
  "mock": { "kind": "test", "title": "Пробная КР", "minutes": 80, "scoreCap": 10,
            "slots": [{ "label": "Формула Байеса", "skills": ["bayes"], "types": ["compute"], "points": 2 }] },
  "topics": [
    { "id": "cond", "file": "cond", "title": "Условная вероятность", "longread": 2, "units": [
      { "id": "bayes", "title": "Формула Байеса", "source": "Лонгрид 2, теорема 1",
        "facets": { "statement": "basic", "proof": "basic" }, "uses": [], "lemmas": ["total-prob"] },
      { "id": "total-prob", "title": "Формула полной вероятности", "source": "Лонгрид 2, лемма 1",
        "facets": { "statement": "basic", "proof": "basic" }, "aux": true }
    ]}
  ]
}
```

- `mock` — ровно `MockSpec` из `src/content/schema.ts`: у коллоквиума `{ "kind": "ticket", "title": "Пробный билет",
  "prepMin": 45, "answerMin": 30, "layout": { "definitions": 4, "statements": 3, "proofs": 1, "taskSlots": [ … ] } }`
  (+ `proofPoints`, `theoryGate`, `scoreCap` по образцу `pilot-colloc`).
- `file` — несколько тем в одном файле (как у образцов); по умолчанию файл = `id` темы.
- Необязательные поля можно не писать. Скрипт проверит id, значок, ссылки `uses`/`lemmas` и темы в позициях.
- Поля конфига пишутся по таблице `CLAUDE.md` §3 — тесты стиля их проверят.
